## Задание
- Запуск нового сервиса Осаго-онлайн
  - пользователь создает заявку
  - предложения от страховых по мере готовности

### Решение
- добавляем компоненты
  - osago-aggregator - новый сервис
    - взаимодействие со страховыми по ОСАГО
      - отправка заявки "создать"
      - опрос до получения результата или истечения 60 секунд
    - горизонтальное масштабирование
  - osago-aggregator-db - новый сервис
    - состояние оркестрации
      - correlationId/quoteRequestId
      - список страховых и статусы (PENDING/RECEIVED/FAILED/TIMEOUT)
      - таймеры/дедлайны (deadline = now + 60s)
      - результаты предложений (offer payload + метаданные)


- интеграции
  - core-app - osago-aggregator: Event Streaming (через Event Broker)
    - core-app публикует событие OsagoQuoteRequested - запрос стоимости
    - osago-aggregator получает и запускает запросы к страховым
    - osago-aggregator публикует события
      - OsagoQuoteReceived - пришло предложение от конкретной стразовой
      - OsagoQuoteFailed - ошибка от конкретной страховой
      - OsagoQuoteTimedOut - истек deadline
    - core-app получает события и обновляет “витрину” статуса для фронта
  - WebApp - core-app + Server Push
    - REST
      - создать заявку 
      - получить текущее состояние полученных предложений - резерв если ошибка Server Push
    - Server Push
      - core-app пушит обновления по заявкам на WebApp, сразу как получил ответ от страховой
      

- паттерны надежности
  - Rate Limiting
    - на входе в core-app (Ingress/API) - для защиты публичных руче
  - Timeout
    - osago-aggregator - страховки:
      - таймаут на каждый вызов HTTP до страховой
    - общий дедлайн жизни (обработки) заявки 60 секунд
  - Retry
    - osago-aggregator - страховки:
      - Retry только на сетевые/временные ошибки
      - обязательно идемпотентность/корреляция (requestId) и дедупликация
  - Circuit Breaker
    - osago-aggregator - страховки:
      - при сработке (открытии предохранителя) - сразу FAIL по этой страховой
